# ADR-0002：厚度输出采用三态可信度，而不是"总是给个数"

- 状态：已采纳
- 日期：2026-10-19
- 相关：§6.3、§7.2、§10.6.4、`common/schemas.py`

## 背景

电网业务最想要的是"几毫米"。但单目 RGB 在没有尺度参考时**物理上无法**给出毫米数：
同一根导线在不同变倍下像素宽度可以差 3 倍。

早期候选方案的处理方式有两类，都不可接受：

1. 直接给像素差或"估计厚度"，不标可信度 → 伪精确，误导决策；
2. 只在有双目/激光测距时才算厚度 → 绝大多数存量摄像头直接不可用。

## 决策

输出 `measurement_status` 三态，并在 Pydantic 层强制约束：

| 状态 | 含义 | 允许输出 |
|---|---|---|
| `measured` | 有 L1（刚性金具）或 L2（PTZ/双目）标定 | 覆盖率、等级、`d_radial`、`d_eq`、`gamma`、`alarm_level` |
| `visual_only` | 只有 L3（晴天建档）或三源不一致 | 覆盖率、等级、`d_radial`（可选）；`d_eq=null`、`alarm_level=null` |
| `not_calibrated` | 无任何尺度参考 | 仅覆盖率与等级；所有厚度与预警字段为 `null` |

`SeverityResult` 的 `model_validator` 在 `not_calibrated` 且带厚度/预警时**抛错**，
用 `raise` 而非 `assert`，避免 `python -O` 下被剥离。

## 三源一致性检验

`fuse_scale_references` 在多源 α 极差 > 20% 时返回 `(None, None)`，上层降级为
`visual_only` + `requires_review=true`。这一条专门针对球机变焦后 `W_0_px` 失效
导致的 2–3 倍系统性偏差 —— 六份候选方案都没写这个细节。

## 代价

- 相当比例的存量机位只能给 `visual_only`，业务方可能觉得"不够用"；
- 需要推动运检部门补 `D_0` 台账与晴天建档图，是组织工作而非技术工作。

## 收益

- 任何输出的可信度可审计、可解释，出问题能定位到"标定失效"而不是"模型不准"；
- 避免用未标定的厚度去驱动除冰决策，这是最危险的使用方式。
