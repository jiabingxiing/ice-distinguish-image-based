# CPU-only 训练预算与取舍

> 本机：LENOVO YOGA 14s 2020 / Ryzen 7 4800U（8C/16T，Zen 2，**无 AVX-512**）/ 16 GB LPDDR4X / **无 GPU**。
> 运行环境：`.venv` Python 3.12.13，torch 2.14.1+cpu，timm 1.0.30。
> 结论先行：**CPU 能训分类与检测的小样本冒烟，不能训到可交付精度；时间要用在"验证链路"而不是"刷指标"。**

## 1. 实测数据（不是估算）

| 项目 | 实测 | 来源 |
|---|---|---|
| 天气分类 1 epoch | **≈6 min**（3422 张，384²，bs16，214 step ≈1.4 s + 验证 46 step） | `docs/weather_p1_report.md` |
| 天气分类 6 epoch | **≈45 min**，test macro-F1 0.891 | `artifacts/reports/weather_eval.json` |

| 物理量算宽度误差 | **0.155 px**（p95 0.377） | `scripts/demo_synthetic.py` |

降级方案（下采样 / 背景差分门控 / ONNX-INT8）都属 P4 可选项，且需重新验证召回。

## 3. 各阶段预算建议

| 阶段 | 数据量 | 建议 epoch | 预计耗时 | 值不值得 |
|---|---|---|---|---|
| P1 天气分类 | 3422 张 | 6（已做） | 45 min | ✅ 已完成，**不再追加**（见 §4） |
| P2 检测冒烟 | 905 张（TTPLA train） | 10 | **50–65 min** | ✅ 值得：证明 GFL 头能收敛 |
| P2 切片基准 | 20 张 4K | — | 3–5 min | ✅ 值得：给延迟上界 |
| P3 合成分割 | 2000 张（可无限生成） | 15–20 | **2.5–3.5 h** | ⚠️ 只在需要 Dice 口径时做 |
| P3 类型/等级头 | 无标注 | — | — | ❌ 无数据，不启动（ADR-0003） |
| P4 端到端 | — | — | — | ❌ 无现场数据 |

**单次会话的可承受上限：约 2–2.5 h 无人值守。** 超过这个量级应改用 GPU 或分批。

## 4. 为什么 P1 不再追加 epoch

1. **收益递减**：best 出现在 epoch 5，epoch 6–7 的 val 未再提升；evaluation log 已显示平台期。
2. **上限是域差**：WEAPD 是网络图（frost/glaze/rime 多为植物特写），现场是低分辨率斜视，
   0.891 与 0.93 的差别不改变"不可用于验收"的结论。
3. **口径问题**：`clear` 类无正样本、强度头无标注 → 这两项无论跑多少 epoch 都是 0。
4. **算力机会成本**：同样的 1 h 用在 P2 冒烟上，能消掉"检测器从未收敛过"这个真实风险。

## 5. 能/不能
  
**能**
- 分类、检测、分割在 1–3 千张量级上跑通并收敛；
- 合成数据上的物理量算验证（不依赖训练）；
- 切片推理延迟基准、长稳测试。

**不能**
- 1080P 实时（1084 ms ≫ 200 ms）；
- 大规模预训练 / 超参搜索 / 消融矩阵；
- 任何以"精度达标"为目标的正式训练 —— 那是 GPU + 现场数据的任务。

## 6. 如果后续拿到 GPU

按改动量从大到小：
1. `configs/train/*.yaml` 的 `train.amp: auto`，batch 提到 32–64；
2. `device: cuda`；
3. 分辨率提到 768/896，epoch 提到 30+；
4. 才谈得上消融与调参。

代码侧无需改动：`TrainConfig.amp` 已支持 `auto`，`resolve_amp()` 会按设备选择。
